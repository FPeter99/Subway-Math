# Long worksheet and homework workflow

Use this workflow whenever the user uploads a worksheet, lesson, scan, PDF, DOCX, or a long list of exercises.

## 1. Read before solving

1. Read the **entire** document, including instructions, headings, examples, notes, figure labels, and appendices.
2. Identify every section explicitly labelled or clearly functioning as **“Kitűzött házi feladat”**, homework, assigned exercise, or required task.
3. Preserve the original order, section number, and subpart labels.
4. Use worked examples in the document as pedagogical context: mirror their level of detail and notation where helpful, but choose a clearer route if it is genuinely simpler and still permitted.
5. Do not solve merely illustrative examples as if they were requested homework unless the user asks for all solutions too.

## 2. Make a compact roadmap

Before the full solutions, provide a short map such as:

| Item | Topic | Main skill | Priority |
| --- | --- | --- | --- |
| 1/a | vectors | vector subtraction and length | core |
| 1/b | vectors | scalar product | core |

Only include this when the document is long enough for it to help. The roadmap is not a substitute for reading every task.

## 3. Solve homework completely

For every assigned task:

- transcribe only the relevant data cleanly; do not reproduce pages of text;
- solve every subpart in order;
- show the method slowly enough to learn from;
- perform the full internal verification protocol before output;
- finish each subpart with a visually distinct result box;
- explicitly mark any unreadable symbol, cropped figure, ambiguous datum, or missing page. Do not invent a value from a blurry image.

If a task is underdetermined, state what is missing and, if useful, solve under a clearly labelled conditional assumption.

## 4. Teach the pattern, not just the answers

After a cluster of similar tasks, add a brief **“Reusable pattern”** or **“Exam checklist”** with the minimum decision rule needed to solve the next similar problem independently.

## 5. Time-aware triage

The stated aim is excellent exam performance under limited time. Categorize only when the worksheet is long, the deadline is near, or the user asks for prioritization:

- **Core / high yield:** foundational technique, common examination type, or prerequisite for later work. Explain in full.
- **Useful variation:** reinforces a core method. Explain the first instance fully; make later repetitions shorter but still correct.
- **Low yield / long routine:** mechanically repetitive or disproportionately time-consuming. Do not skip without notice. State why it is low-yield, give a concise correct solution pattern or one representative fully solved instance, and recommend what to do next.

Never call a task “unimportant” merely because it is easy. The issue is learning value relative to time.

## 6. Completion check

Before saying the worksheet is done, verify:

- every labelled homework item was addressed;
- every subpart has a final answer or an explicit reason it cannot be resolved;
- numbering agrees with the source;
- no example was accidentally substituted for a homework task;
- formulas obey the source-policy boundary.
